## Why this matters

The "Servicio (Catálogo)" dropdown in the new-order form and the admin catalog
page render a flat, ungrouped list. The business provided the full NE4 rate
card (~55 services across 5 categories, including pack prices and
"según oferta" / price-on-request items). After this plan: the catalog has a
`category` column, both UIs group by category, and the NE4 rate card is seeded
idempotently so admins can create billable NE4 orders without manual data entry.

### Step 2: Write migration `022_service_item_categories.sql`

Header per convention (`Depends on: 021_team_pins.sql` — adjust if renumbered). Contents, in order:

1. `ALTER TABLE public.service_items ADD COLUMN IF NOT EXISTS category TEXT;`
2. Recreate the public view **including `category`**: copy the exact view from the "Current state" notes (migration 014: `DROP VIEW IF EXISTS public.service_items_public; CREATE VIEW ... ; GRANT SELECT ON public.service_items_public TO authenticated;`) and add `si.category,` to the select list after `si.unit,`.
3. Seed with a CTE upsert. Pattern (pure SQL, no PL/pgSQL — matches migration 004's documented style):

```sql
WITH new_items (code, description_de, unit, unit_price, category, detail_form, operator_code, client_code, display_order) AS (
  VALUES
    ('NAS_DGF_ACT_003', 'HÜP-GFTA-ONT, Fusion + Bohrung', 'Units', 184.00, 'NE4 > ONT / Aktivierung', 'alta', 'DGF', NULL, 100),
    -- ... all rows from the table below ...
    ('NAS_DGF_BAUM', 'Handschachtung Bäume', 'ML', 72.00, 'NE4 > Suplementos / Mehraufwand', NULL, 'DGF', NULL, 540)
)
INSERT INTO public.service_items
  (code, description_de, unit, unit_price, category, detail_form, operator_id, client_id, display_order, active)
SELECT ni.code, ni.description_de, ni.unit, ni.unit_price, ni.category, ni.detail_form, o.id, c.id, ni.display_order, true
FROM new_items ni
LEFT JOIN public.operators o ON o.code = ni.operator_code
LEFT JOIN public.clients  c ON c.code = ni.client_code
WHERE NOT EXISTS (SELECT 1 FROM public.service_items si WHERE si.code = ni.code);

-- Categorize rows that already existed (same codes, seeded earlier):
WITH cats (code, category) AS (
  VALUES ('NAS_DGF_ACT_003', 'NE4 > ONT / Aktivierung') -- ... one row per code below ...
)
UPDATE public.service_items si SET category = cats.category
FROM cats WHERE si.code = cats.code AND si.category IS NULL;
```

VALUES typing note: in the `new_items` CTE, cast the first row's columns explicitly if Postgres complains (`184.00::numeric`, `'alta'::text`); NULL prices must be written `NULL::numeric` in the first row they appear.
